# B-1: SerwistProvider must not reload the page when the connection returns

**What** (`src/app/layout.tsx`, frozen):

```diff
-<SerwistProvider swUrl="/serwist/sw.js" disable={process.env.NODE_ENV === "development"}>
+<SerwistProvider swUrl="/serwist/sw.js" disable={process.env.NODE_ENV === "development"} reloadOnOnline={false}>
```

**Why.** `@serwist/turbopack`'s provider defaults to `reloadOnOnline: true`: it calls `window.location.reload()` on every `online` event. A gym phone that drops and regains signal mid-workout would reload the workout screen (losing in-memory UI state such as an open rest-timer sheet or a half-typed set). This conflicts with "never disturb a workout" (docs/agents/B.md, service-worker section). Offline logging itself is Dexie-backed so no data is lost, but the reload is jarring.

**Workaround.** None in B's paths (the prop lives in the frozen layout). The shell's own update flow never reloads during a workout; only this provider default can. Until applied, the reload on reconnect stays.

# Stream DIAL: the Calibrated Dial redesign

Owner request: replace the editorial look (paper, Instrument Serif, vermilion) with direction **A+B “Calibrated Dial”**: a rubber-floor dark palette built from competition plate colours, condensed italic Archivo, and a plate-face rotary dial for weight entry on phones, with an equipment picture that reacts as the dial turns.

**The spec is the source of truth:** `docs/design/calibrated-dial-handoff.html` (tokens, layout, components and props, equipment pictures, dial behaviour, states, motion, content rules, edge cases, accessibility, haptics (dropped), decisions D1–D7, definition of done). The visual reference, with working SVG geometry and dial code you may port, is the `#dial` section of `docs/design/overload-directions-mockup.html` (search for `A+B · CALIBRATED DIAL`). Read the spec in full before writing code.

Ownership is unrestricted for this stream (`ownership.json`), but **each agent stays inside its own part below** so parallel branches merge cleanly. List every frozen file you changed in your report.

### Part PERF-3 (added after the phone test): sync policy, background work, bundle and data
**Sync policy** (header of `src/client/sync/engine.ts`, CONTRACTS.md section 3). The flag is `isWorkoutActive()` (`src/lib/pwa.ts`, set by `ActiveWorkout`, cleared by finish and discard).
- Outside a workout: app start; 1.5 s after a write (`WRITE_DELAY_MS`); every 30 s while changes are pending (`PENDING_INTERVAL_MS`, the retry); `online`; `visibilitychange` at most once per 30 s (`VISIBILITY_MIN_MS`); manual.
- During a workout: app start; manual; and at most one sync per 5 minutes (`WORKOUT_SYNC_INTERVAL_MS`) while changes are pending. Writes and `visibilitychange` trigger nothing, `online` is throttled to the same 5 minutes. Changes are safe in Dexie meanwhile.
- The flag turning off (finish, discard, or another tab) syncs at once (`onWorkoutActiveChange`). A manual sync waits for a running one instead of being skipped.
- A request with no mutations is answered without a write transaction (`src/server/sync/apply.ts`, `pullOnlyOutcome`). The catalog is re-checked at app start and every 6 hours, not on every sync.
- `workout/SyncNow.tsx` is the "Sync now" button under the workout bar (unsynced row count, progress, outcome in an `aria-live` region). `client/sync/persist.ts` asks for persistent storage (twice at most per browser: after sign-in and at the first workout).
**Other changes**: `SyncProvider` leases its engine (the engine survives the (app) / (workout) switch; moving the route folders under a shared parent is blocked by the frozen `ownership.json`, whose test lists every tracked file); `PwaClient` warms `/workout` and `/today` once per service-worker version (`sw.ts` answers `GET_VERSION`) in idle time; `shell/useTabPrefetch.ts` prefetches the neighbouring tabs on phones (`router.prefetch` is a full prefetch cached for `staleTimes.static`, now 30 s); the active workout is found through a meta pointer (`client/db/active-workout.ts`, Dexie schema version 3); `bulkPut` skips unchanged pulled rows; the exercise list and search index are kept in memory (`repo.ts`, `db.exercisesGeneration`); the picker uses `useDeferredValue`; `HistoryList` pages by 20; `/exercises` uses `next/form`, a cached slim catalog (`server/catalog/queries.ts`) and optimized photos; recharts loads lazily (`charts/lazy.tsx`); Tailwind skips `prisma/`, `docs/`, `e2e/` and other non-markup folders; `/workout` renders a skeleton instead of "Loading…". Skipped: preloading only the upright Archivo face (the italic is the display face on every first screen, so a late italic would shift headings).
